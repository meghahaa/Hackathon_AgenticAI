Gemini is the **only** generative model provider in the committed evidence. An optional Groq quota fallback
(`QUOTA_FALLBACK_PROVIDER=groq`, [README → Configuration](../README.md#configuration)) exists for when Gemini quota
runs out. It is **off by default** (`QUOTA_FALLBACK_PROVIDER=none`), and the committed evidence contains **0 Groq
calls** (`eval_report.json` → `summary.groq_calls_by_step`, `judge.usage.groq_calls`; `golden_signals.json` →
`providers.groq_calls_by_step`; `redteam_results.json` → `summary.groq_involved_attacks`; no `quota_fallback` audit
record). `langchain-openai`/`langchain-anthropic` packages are present only as transitive dependencies of
`langmem`/`deepeval` and are never imported by this codebase.

History: `gemini-2.5-flash` returned 404 ("no longer available to new users") and
`gemini-3.8-flash` / `gemini-3.6-flash` returned sustained 503 "high demand" during development;
the model choice and the fallback chain are the result (see
[failure-analysis.md](failure-analysis.md) and [optimization-note.md](optimization-note.md)).

## 2. What the LLM is and is not allowed to decide

| Decision | Made by | Why |
|---|---|---|
| Readmission-risk tier (LACE + social modifier) | Deterministic code, [`src/clinical_rules.py`](../src/clinical_rules.py) `compute_lace` | Reproducible, auditable; the LLM only writes the rationale and a tier contradiction is rejected. |
| Follow-up windows per condition | Deterministic rules keyed to **retrieved** policy sections (`rule_requirements`) | A requirement is only emitted if its policy section was actually retrieved (citation grounding). |
| Medication list | Copied from orders by code; SHA-256 fingerprint verified (`verify_orders_unchanged`) | The copilot must never alter clinical orders (AC-01, POL-MED-08). |
| Appointment slots | MCP tool `find_followup_slots` | Tool data, not generated. |
| Intent classification | Gemini + deterministic safety overrides (`rule_intent`) | Order-change and out-of-scope requests can't be mis-routed by the model alone. |
| Policy search queries (policy questions) | Gemini in a bounded tool-calling loop: `bind_tools([search_followup_policy])`, max 3 tool calls (`POLICY_TOOL_CALL_CAP`), unknown tool names rejected, every call through `call_tool` (logged + traced); up to 2 Gemini query rewrites when a search grades insufficient (`POLICY_MAX_REWRITES`) | The model chooses *what to search*, code bounds *how much* and checks citations. Offline or on error it falls back to the deterministic query and records a degradation ([`tests/test_agentic_policy.py`](../tests/test_agentic_policy.py)). Current run: 16 `policy_tool_loop` calls over 8 policy questions, 0 Gemini rewrites needed. |
| Patient instructions, red flags, rationale, policy answers | Gemini, grounded on retrieved excerpts; dose-grounding filter and citation validation | Language generation is the model's job; the guardrails check the facts it uses. |
| Approval / finalisation | `human_approval_gate`, then the `clinician_signoff` interrupt; **only a clinician resume** approves | HIGH risk etc. are held. Every drafted plan / schedule and every order-change request pauses (LangGraph `interrupt`) until a clinician approves, rejects or requests changes; no code path sets `APPROVED*` otherwise ([`tests/test_hitl.py`](../tests/test_hitl.py), [output-risk.md](output-risk.md#clinician-sign-off-a-real-pause-langgraph-interrupt)). |

## 3. Data

* **All synthetic**, produced by [`scripts/generate_synthetic_data.py`](../scripts/generate_synthetic_data.py)
  (fixed seed): 8 patient records ([`data/synthetic_patients/`](../data/synthetic_patients/)) with fabricated
  names/MRNs/phones/addresses, 8 policy documents ([`data/policy_corpus/`](../data/policy_corpus/)), a clinic
  schedule ([`data/clinic_schedule.json`](../data/clinic_schedule.json)).
* One record (pref_fb868fac49) deliberately contains a prompt-injection string in its free-text nursing
  note to exercise quarantine (NFR-03). Two more (pref_137b9b1c4b, pref_43875e328c) carry reworded injections for
  the red-team set (RT20 / RT21, [failure-analysis.md](failure-analysis.md) F10).
* Demographics never leave the MCP server (`deidentify_record`); logs and traces carry an HMAC
  pseudonym (`pref_…`) instead of the patient ID.
* **What reaches Gemini:** every Gemini request is PHI-masked at one point, after the input guard has seen the raw
  text: `RateLimitedChatGoogleGenerativeAI._prepare_request` and `get_num_tokens` in [`src/llm.py`](../src/llm.py)
  (agent calls, the tool loop, LangMem), and the DeepEval judge masks its own prompt in
  [`src/eval_judge.py`](../src/eval_judge.py). Canonical and loose patient ids become `pref_` pseudonyms; registry
  identifiers and PHI patterns are masked ([`tests/test_gemini_phi_egress.py`](../tests/test_gemini_phi_egress.py)).
  Limit: egress masking is registry + regex (no NER), so a free-text name that is in no record and matches no
  pattern could still reach the model.
* No training or fine-tuning: models are used as-is via API.

## 4. Intended use

Help a discharge coordinator or clinician **draft** a discharge plan: reconcile the order list
(verbatim), identify readmission-risk factors, retrieve and cite follow-up/home-care policy, propose
follow-up appointments within policy windows, and route anything consequential to a clinician.
Users: licensed clinicians and care coordinators, in a supervised workflow.

## 5. Out of scope / not intended

* Any clinical judgement: diagnosis, prescribing, dose changes, stopping medication (such requests
  are refused and routed: `clinical_order_change` intent).
* Real patient data, real EHR/scheduling integration, autonomous booking or finalisation.
* Patient-facing use without clinician review; languages other than English.
* Containerised/cloud deployment (out of scope for this cut).

## 7. Known limitations and failure modes

Documented with trace/log evidence in [failure-analysis.md](failure-analysis.md):

1. **Model availability**: Gemini preview models return 503 under load; the fallback model is then
   used. Latency rises and quality may differ (F1).
2. **Latency**: per-turn latency is dominated by sequential LLM calls under the client-side request
   budget (F2, [optimization-note.md](optimization-note.md)).
3. **Ungrounded free text / context leakage**: the plan narrative (instructions, red flags) and the
   risk rationale are LLM-written. Dose mentions are filtered against orders, but symptom lists may
   include items not in the policy corpus, and a stale record field once leaked into the rationale
   (F3, fixed by context isolation). DeepEval hallucination/faithfulness scores quantify this.
4. **Degraded mode**: without Gemini the system uses rule-based fallbacks; outputs are marked and
   the gate holds them for review (`partial_degradation_requires_review`).
5. **Evaluation scale**: the golden set has 32 cases, all judged (the judge is independent of the agent model
   since Final run v1, F5). Non-answers can score 0.0 on HallucinationMetric without inventing anything, so the
   headline is the rate on answers. Scores are indicative, not statistically robust.
6. **Scope of the risk model**: LACE is a simplified synthetic protocol, not a validated clinical
   model for this population.
7. **Session facts** are extracted by deterministic patterns (weekday, driver, transport,
   telehealth); facts phrased differently may be missed.
8. **English only**. Injection detection (regex + LLM Guard classifier) can be evaded by novel phrasing: the
   red-team set found an approval-bypass instruction that was escalated rather than refused (F8), and two
   record-embedded instructions written as clinical notes that neither layer detected (F10, accepted residual risk).
   Code-computed risk tiers, scope-locked tools, the output guard and the clinician sign-off pause are layered
   behind it.
9. **Cross-patient phrasing**: a request naming another patient by location ("the patient in room 12") was not
   refused. The tool scope lock kept the turn on the session's own patient (F11).
